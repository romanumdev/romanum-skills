# Roblox thumbnail design

Make the player understand the game and the feeling of playing it in one glance. Establish the real mechanic, audience and placement from the brief. Ask only for missing information that changes the image; do not turn a generation request into a questionnaire.

For brainrot, incremental, collecting or younger-audience games, read [the audience guide](references/brainrot-and-younger-audiences.md). When using bacon hair, acorn girl or the wicked grin, open the actual images in [the character reference pack](references/characters.md) and pass the relevant files to the image tool. A written description alone is not an identity reference.

## Three reads

- **Setting / fantasy:** a conveyor, delivery doorstep, growing plot or other recognisable game environment.
- **Emotion:** an immediately readable face and pose: outsmarting, panic, triumph, surprise or anticipation.
- **Core action:** show what the player actually does, especially the game's distinctive mechanic.

The character anchors these reads. A beautiful portrait with no understandable action is not a finished thumbnail. A busy scene with a tiny face also misses the brief.

## Make the image

1. Classify inputs as character/outfit, expression, environment, composition, or a negative example. Preserve only what each reference is meant to establish. Never import another game's mechanics from its thumbnail.
2. For an open brief, suggest up to three short, distinct concepts and recommend one. When generation is requested and the brief is sufficient, choose a fitting concept and generate directly. Do not require another approval for already-authorised work.
3. Build the prompt around setting, character identity, exact action, expression, camera, lighting and minimal text. Use the available image-generation tool and reference inputs; do not substitute a prompt for a requested image. Respect the configured provider and spending permissions.
4. Inspect the generated result before delivering it. Check anatomy, hair/outfits, facial intent, hand-to-prop contact and whether the action is physically understandable. Correct the most important failure while preserving the successful parts.
5. Check at a small display size (roughly 320 x 180 for a thumbnail; 128 x 128 for an icon). The face, action and main object should still read. Deliver the image with a short concept label; keep critique and generation notes separate from the artwork.

Default thumbnails to 16:9; icons to square, at least 512 x 512. Compose icons around one dominant subject and expression rather than cropping a complex thumbnail. Keep essential content clear of edges and possible interface overlays. Use text only when it adds information the image cannot convey, and quote the exact words in the prompt. Never use invented rewards, odds or numbers as if they are real game values.

For regeneration, retain the prompt, reference roles and selected output. Refer back to the canonical character images on each run; repeated edits of generated copies can drift. If a tool cannot see the reference files, say so rather than claiming an identity-matched result.

## Evidence before style

Classify each reference: owned experiment with impressions/clicks and dates, authorised visual inspiration, or an unmeasured public thumbnail. Popularity of the game is not thumbnail CTR. Call a reference high-performing only when its measurement, audience, placement and test window support that description. With no such dataset, use composition hypotheses and propose a test; never fill in a CTR or imply a visual score predicts clicks.

Study the communication rather than copy the image: focal action, readable expression, contrast, scale, and how the title and image complement each other. Use third-party assets only with appropriate rights. Distinctive characters, branding and layouts are not free assets merely because they appear in a reference.

## Useful variants

For concept exploration, change the story or viewpoint: a trap being set, a narrowly avoided trap, or a reward reveal are different ideas; recolouring the same scene is not. For a controlled test, change one intended variable and hold the rest steady. Do not force every concept into split-screen, a chase or a winner/loser pairing.

Test concepts against the same placement/audience where possible. Track exposure, qualified plays or clicks using the metric actually provided; do not treat CTR and qualified play-through as interchangeable. Separate creative effects from traffic mix, concurrent updates and sampling noise. State a stopping rule before testing; an early winner is not a guaranteed improvement.
